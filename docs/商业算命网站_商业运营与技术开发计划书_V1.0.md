## 一、项目总目标

本项目拟将现有 `bazi-skill` 从“Claude Code 八字 Skill”升级为一个可持续运营的商业化传统命理与文化研究平台。平台的核心竞争力不是简单生成一段“算命文案”，而是建立“确定性排盘引擎 + 可追溯规则库 + AI解释层 + 用户长期档案 + 可视化报告”的完整系统。

建议产品采用双轨定位：

1. **中国大陆合规版**：定位为传统文化研究、历法与命理知识工具、娱乐体验，禁止绝对化预测、恐吓式营销、改运保证、替代医疗/法律/投资/婚姻重大决策等内容；正式收费和上线前必须进行专项法律合规审查。
2. **海外版**：可提供更完整的 Bazi / Zi Wei Dou Shu / I Ching entertainment reading，但仍必须明确娱乐与文化属性，并遵守当地消费者保护、隐私、支付和 AI 内容规则。

### 项目一句话定位

**“把传统命理从黑箱式算命，升级为可计算、可解释、可追溯的 AI 中国传统文化分析平台。”**

## 二、核心产品原则

### 2.1 计算和解释严格分层

系统必须坚持：

- Python / TypeScript 规则引擎负责历法、四柱、十神、藏干、神煞、大运、流年、紫微星盘等确定性计算；
- AI 只负责解释、组织语言、引用规则、生成个性化报告；
- AI 不得覆盖确定性引擎的盘面结果；
- 每一项关键结论应尽可能附“规则依据 / 经典出处 / 置信度”。

### 2.2 不做“AI胡算”

用户输入出生资料后，所有命盘必须先经过排盘引擎；AI 不得自行口算四柱、节气、农历或大运。

### 2.3 结果必须可审计

每份报告保存：

- 原始输入；
- 标准化后的出生时间；
- 时区；
- 真太阳时校正前后值；
- 使用的排盘口径；
- 引擎版本；
- 规则库版本；
- AI 模型与提示词版本；
- 生成时间；
- 关键结论来源。

这使同一命盘在同一版本下可复现。

## 三、合规红线与上线前置条件

### 3.1 中国大陆互联网信息服务风险

现行《互联网信息服务管理办法》规定，经营性互联网信息服务实行许可制度；同时禁止制作、复制、发布、传播包括“宣扬邪教和封建迷信”等违法信息。传统命理产品与该条款存在明显的内容合规风险，因此“娱乐免责声明”本身并不能自动解决合规问题。

**大陆正式上线前必须完成：**

- 公司主体和经营范围审查；
- ICP/增值电信业务许可路径审查；
- 产品定位和内容规则专项律师意见；
- 用户协议、隐私政策、付费协议、退款规则审查；
- 广告文案审查；
- AI 生成内容合规审查；
- 数据跨境与第三方模型调用审查。

### 3.2 AI 生成内容标识

如果面向中国境内公众提供生成式 AI 文本、图片等服务，应根据适用规则实现显式/隐式标识、服务协议说明、日志与相关合规能力。2025 年 9 月 1 日起实施的《人工智能生成合成内容标识办法》应在产品设计阶段直接纳入架构，而不是上线后补丁式处理。

### 3.3 个人信息保护

姓名、出生日期、出生时间、出生地点、联系方式、支付记录以及用户主动提供的家庭/健康/感情/财务经历都可能构成个人信息；部分信息在具体场景下可能达到敏感个人信息风险等级。

原则：

- 能匿名排盘就不强制实名；
- 出生姓名不作为排盘必填项；
- 出生地只存标准化行政区/经纬度，不保留不必要的详细住址；
- 历史事件校准必须明确告知用途；
- 默认禁止把用户隐私用于模型训练；
- 提供数据导出、删除账户、删除命盘能力；
- 未成年人功能单独设计，V1 建议直接限制 18 岁以上使用付费个性化服务。

### 3.4 内容安全禁区

产品层面直接禁止以下类型输出：

- “你一定会得某种病 / 在某年死亡”等死亡、疾病确定性预测；
- 用灾祸、死亡、离婚、破财等恐吓用户付费；
- “交钱可以消灾/改命/保发财”等保证式营销；
- 代替医生、律师、证券分析师、心理治疗师作重大决策；
- 鼓励用户基于命理进行高风险投资、借贷或赌博；
- 对第三人进行侮辱、诽谤、人格贬低；
- 诱导用户形成依赖性消费。

## 五、商业模式建议

### 5.1 收入结构

建议目标收入结构：

- 订阅：50%～60%；
- 单次报告：25%～35%；
- 专业版/API/创作者工具：10%～15%；
- 合规的传统文化课程、书籍、周边：0%～10%。

### 5.2 定价方法

第一阶段不追求高客单价，重点验证：

- 免费用户 → 首次付费转化率；
- 首次报告 → 月订阅转化率；
- 30 日留存；
- AI 成本 / 付费用户；
-退款率和投诉率。

建议先做 A/B 定价，不在代码中写死价格。通过后台配置价格、优惠、套餐、区域币种。

### 5.3 毛利控制

AI 是主要可变成本之一。报告生成采用“规则先算 + 小模型整理 + 高价值部分再调用强模型”的分层策略：

- 免费简版：模板 + 低成本模型；
- 付费完整版：强模型；
- 长对话：摘要记忆 + 上下文裁剪；
- 经典文本检索：RAG，只检索相关章节，避免整库塞入上下文。

目标：成熟阶段 AI + 基础设施变动成本控制在收入的 15%～25%以内。

## 七、技术总架构

建议采用“前后端分离 + 确定性命理引擎 + AI 服务层”的架构。

```text
Browser / Mobile Web
        |
        v
Next.js Web Frontend
        |
        +------------------+
        |                  |
        v                  v
FastAPI Backend      Ziwei Server Module
        |              (iztro / Node)
        v
Application Services
        |
        +---------+---------+---------+
        |         |         |         |
        v         v         v         v
Bazi Engine   Calendar   Rule/RAG   AI Gateway
        |         |         |         |
        +---------+---------+---------+
                  |
                  v
          PostgreSQL / Redis
                  |
                  v
        Object Storage / Logs
```

### 7.1 前端

建议：

- Next.js + TypeScript；
- Tailwind CSS；
- 图表使用成熟可商用库；
- SSR/SSG 用于 SEO 内容页；
- 命盘页面采用动态渲染；
- i18n：简体中文、繁体中文、英文优先。

### 7.2 后端

建议：

- Python FastAPI；
- Pydantic 数据校验；
- SQLAlchemy；
- PostgreSQL；
- Redis 缓存与限流；
- 队列处理长报告；
- 对象存储保存 PDF/图片；
- OpenTelemetry / Sentry 类错误追踪方案。

### 7.3 AI Gateway

不把业务逻辑直接绑死到单一模型。

统一接口：

```text
analyze_bazi(chart, user_context, tier)
analyze_ziwei(chart, user_context, tier)
follow_up(session, question)
generate_report(report_id, format)
```

Gateway 内部支持不同模型提供商，通过配置切换。

## 十、知识库与 RAG

### 10.1 知识来源分层

A 层：公共领域古籍原文；  
B 层：经授权的现代注释；  
C 层：项目自建规则解释；  
D 层：用户历史反馈（只在取得明确授权后使用）。

### 10.2 知识结构

每条知识单元包含：

- 原文；
- 书名；
- 卷/章节；
- 现代释义；
- 适用条件；
- 不适用条件；
- 正例；
- 反例；
- 对应程序规则 ID。

### 10.3 禁止做法

- 不把网络“算命文案”无来源抓取后当经典；
- 不大规模复制现代版权命理书；
- 不让 AI 虚构古籍引用；
- 引用找不到出处时明确显示“项目规则解释”，不得冒充经典原文。

- 输出分类器；

核心原则：**工具页带自然流量，知识页建立权威，免费排盘承接转化。**

### 14.2 社交传播

分享卡片重点展示结构化内容，而不是恐吓式文案：

- 五行分布卡；
- 四柱卡；
- 紫微星盘卡；
- 传统文化知识卡；
- 年度学习/自省主题卡。

### 14.3 用户留存

合法合规前提下，可用：

- 收藏命盘；
- 每月传统历法提醒；
- 新增经典注释提醒；
- 年度报告更新；
- 新功能体验。

不要通过“灾祸即将发生”制造焦虑召回。

## 十九、商业护城河

真正的护城河不是 Prompt，而是以下五项资产：

1. **经过大规模回归验证的排盘引擎；**
2. **高质量、合法来源、可追溯的传统规则知识库；**
3. **命盘事实 → 规则证据 → AI解释的可审计链路；**
4. **优秀的命盘可视化与产品体验；**
5. **长期积累的匿名质量反馈与测试样本。**

Prompt 可以被复制，稳定的引擎、知识库、数据质量和用户信任不容易复制。
