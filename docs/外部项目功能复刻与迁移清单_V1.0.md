# 外部项目功能复刻与迁移清单 V1.0

目标不是把几个开源仓库机械堆叠，而是在可商用许可证边界内，把优秀功能统一为本项目自己的产品与接口。

## 总原则

| 来源项目 | 代码能否直接商用 | 本项目处理方式 |
|---|---|---|
| jinchenma94/bazi-skill | 可以，MIT | 当前仓库已 Fork，继续演进 |
| 6tail/lunar-python | 可以，MIT | 依赖 + Adapter + 双引擎核验 |
| SylarLong/iztro | 可以，MIT | npm 依赖 + 紫微服务封装 |
| HeiGeAi/HeiGe-SuanMing | 不可直接商用（PolyForm Noncommercial） | 只借鉴功能，clean-room 重写 |
| china-testing/bazi | 无明确许可证，不可默认商用 | 只借鉴功能，重新实现 |

## F. 历法基础设施

优先使用/核验 `lunar-python`，本项目保留自己的计算引擎用于独立验证。

统一接口：

```python
calendar.to_lunar()
calendar.to_solar()
calendar.solar_terms()
calendar.ganzhi()
calendar.true_solar_time()
```

所有术数共享同一时间、时区、经纬度和节气基础设施，避免每个模块各算一套。

## G. AI 解释层

外部项目的 Prompt 不直接当成核心资产复制。本项目重新设计统一结构：

```text
确定性事实
  -> 规则命中
  -> 原典/项目规则证据
  -> 风险过滤
  -> AI解释
  -> 引用与置信度
```

每条关键结论必须能回溯到：

- chart fact
- rule_id
- source_id
- prompt_version
- model_version

## I. 复刻完成定义

“复刻”不等于文件数量相同，而是功能达到或超过参考项目，并满足：

1. 可商用许可证无缺口；
2. 每个确定性模块有自动测试；
3. 输出结构统一；
4. 同一输入可复现；
5. AI 不参与基础排盘数学；
6. 商业网站可通过 API 调用；
7. 生产环境可监控、可回滚、可审计。
